# How to start a new project

There are two shapes a new project takes, and it is worth asking which one applies if it is not obvious from context: a software or work project, or a life area such as health, finance, a job search, or a trip.

## A software or work project

Look at what already exists in the folder first, and never overwrite a file that is already there; only what is genuinely missing gets created. A well-set-up project has an entry point every AI reads first, kept short, covering what the project is, its stack, where things live, the files to read first, and the project's own rules. A running handoff file records where the work stands, what is done, what is next, open questions, and how to run and test it, updated at the end of every session rather than left stale. A changelog records what happened, dated and newest first, written as it happens rather than reconstructed afterward. A decisions file holds each decision, its date, the options considered, and why the chosen one won, kept separate from the changelog rather than mixed into it. A structure file gives the folder tree with one line per important file and how data flows through it, updated whenever files move.

Whatever can genuinely be inferred from the code itself, such as the language, framework, and commands, gets filled in directly; anything that cannot be inferred gets marked as unknown rather than invented.

## A life area

A life area gets a profile of the person's current situation, marking unknowns rather than guessing at them; an operating plan written only after research and the person's own answers are in hand; goals split into short, medium, and long term; a log per thing being tracked, starting with just a header row; the latest research findings; and a handoff describing where things stand and what is next.

Three things happen at the same time rather than one after another: the folders and files get created with headings and placeholders in place, a background research task starts on best practices for this person's actual situation, place, and constraints with real sources, following [[reference_how_to_research_with_sources]], and four to six focused questions go out in one message covering the current situation, the relevant numbers such as money or time, the goals, the constraints, and whatever tools are already in use. Round numbers are perfectly fine at this stage.

Once the answers and the research are both in, the profile gets filled in, the plan gets written from the research applied to the person's actual numbers, and a short summary highlights the single insight that matters most.

## Both kinds

No number ever gets invented; anything not yet known stays marked as unknown until the person supplies it. Once set up, the project itself becomes a memory: what it is, where its folder is, and its goal, following [[reference_how_to_save_a_memory]], so a later recall finds it from any conversation. Every setup ends by asking the one question that actually moves the project forward next.
